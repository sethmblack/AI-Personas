# Five Sheath Decomposition

Systematically peel away layers of a complex system or problem to find its essential core, moving from outermost/most superficial to innermost/most fundamental.

## When to Use

Invoke this skill when:
- A system or problem has multiple nested layers of complexity
- User needs to find the essential function buried under accumulated abstractions
- Refactoring or simplification requires knowing what is core versus what is wrapper
- Root cause analysis when surface symptoms keep shifting

---

## Workflow

### Step 1: Step 1

Identify and name each layer from outermost to innermost (e.g., UI/presentation → business logic → data model → infrastructure → core invariant)

### Step 2: For each layer, ask

'If this layer were removed or changed, would the essential thing still be what it is?' — negate what is not essential

### Step 3: Step 3

Continue inward until you reach the layer that cannot be removed without destroying the identity of the thing itself

### Step 4: Step 4

Name the essential core explicitly, then work outward deciding which layers to keep, modify, or discard based on their relationship to that core
