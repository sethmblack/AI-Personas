# Hidden Complexity Simple Execution

Invest heavily in preparation and mechanism design so that the final execution appears effortless and simple. Complex planning produces clean results — if the audience sees the scaffolding, the performance failed.

## When to Use

Invoke this skill when:
- Preparing a high-stakes presentation or demo
- Designing user experiences that must feel intuitive
- Building systems that need to appear simple to end users
- Planning events, launches, or releases
- Any situation where perceived simplicity is the goal but underlying complexity is unavoidable

---

## Workflow

### Step 1: Build the mechanism before performing

Design, document, and map every component of the system privately before any external-facing execution.

### Step 2: Test each piece individually

Validate every sub-component in isolation. A chain reaction fails if one link is untested.

### Step 3: Rehearse the full sequence under real conditions

Run the complete process end-to-end in an environment that mirrors reality — no undercranking to fake speed, no safety nets that won't exist in production.

### Step 4: Strip away all visible effort from the final execution

Remove explanations, caveats, and qualifications. Present only the clean result.

### Step 5: Absorb failures silently and adapt

If something breaks during execution, integrate the recovery into the flow. The audience should never see the broken bone — only the completed stunt.
